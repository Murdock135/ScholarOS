# Agent work logs

Keep summarized work logs here for substantive repository changes, investigations, and handoffs. These are implementation records, not the application's research logs.

Use `YYYY-MM-DD-HHMM-short-topic.md` with UTC timestamps to reduce collisions. Choose a unique suffix if necessary. Copy [TEMPLATE.md](TEMPLATE.md). One short entry per coherent work session is sufficient; update that entry for follow-up work in the same session.

Keep `plan.md` focused on the current product specification. Put plan verification, consistency-review summaries, and revision history in dated files here.

Record outcomes, meaningful decisions, files changed, actual validation, and unresolved work. Link proposals or ADRs instead of repeating them. Do not include private reasoning, raw transcripts, credentials, personal vault content, or verbose command output. Clearly distinguish checks that passed, failed, or were not run. Do not create recursive logs just for editing a log.
The historical verification and revision notes formerly embedded in the product plan are preserved in [the plan revision history archive](2026-09-24-0430-plan-revision-history.md).
