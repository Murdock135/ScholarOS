# Proposals

Use proposals for meaningful unresolved product or technical choices, experiments, and scope changes. Keep routine implementation choices in the work log.

Use `YYYY-MM-DD-short-title.md` and copy [TEMPLATE.md](TEMPLATE.md). State assumptions and distinguish established facts from suggestions. Link relevant [plan](../../plan.md) sections and [ADRs](../adr/README.md).

When a proposal is resolved, update its status and record the basis. For an accepted architectural choice, create an ADR; update the plan when product behavior or scope changes. A proposal file alone does not authorize external actions or establish user agreement.
